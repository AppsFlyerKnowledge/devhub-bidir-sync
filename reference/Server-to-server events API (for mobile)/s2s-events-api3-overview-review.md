The AppsFlyer platform attributes and records mobile app events sent by the AppsFlyer SDK and by S2S APIs.

## Endpoint

```http
POST https://api3.appsflyer.com/inappevent/{app_id}
```

<Callout icon="📘" theme="info">
### New — high-volume sending

For bulk or backfill sending, ramp up gradually (e.g. +2K TPS/min) rather than sending at full volume immediately, and implement retry logic for errors.
</Callout>

## Prerequisites

S2S key. Learn [how to obtain the S2S key](https://support.appsflyer.com/hc/en-us/articles/360004562377-Managing-API-and-Server-to-server-S2S-tokens).

<Callout icon="🚧" theme="warn">
### New — revenue not recording

If `eventValue` isn't stringified before sending, the request still returns `200 OK` but revenue is silently dropped:

```json
"{\"af_revenue\":\"6\" ,\"af_content_type\":\"wallets\"}"
```

`af_revenue` must also be unformatted: no currency symbols or thousands separators, decimal point allowed, leading `-` for negative values (refunds).

- Valid: `123`, `-123.45`, `123.456`
- Invalid: `1,234.56`, `1,234`
</Callout>

<Callout icon="🚧" theme="warn">
### New — event time-stamping logic

Events are stamped with `eventTime` only if they arrive before 02:00 UTC on the day after the event occurred; later arrivals are stamped with arrival time instead, shifting attribution dates. Send same-day events before this cutover.

**Example:** an event occurs Monday at 21:00 UTC (`eventTime` = Monday 21:00).

| Arrives at AppsFlyer | Timestamp used | Why |
| --- | --- | --- |
| Tuesday 01:00 | Monday 21:00 | Arrived before the 02:00 UTC cutover, so `eventTime` is honored. |
| Wednesday 09:00 | Wednesday 09:00 | Arrived after the cutover, so the arrival time is used instead. |
</Callout>

<Callout icon="📘" theme="info">
### New — metaweb_int only

Events sent to the `metaweb_int` endpoint must include `ua` (user agent) and `ip` explicitly. Meta requires these to optimize campaigns via the Conversions API. Unlike SDK-originated events, they aren't auto-populated for S2S calls.
</Callout>
